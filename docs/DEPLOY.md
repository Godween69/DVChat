# Как развернуть свой DVChat

Инструкция для тех, кто скачал исходный код и хочет запустить собственный мессенджер
на своём сервере. Код приложения не содержит ключей и адресов чужих служебных сервисов,
поэтому всё нужное вы подключаете сами. К серверу автора приложение не подключится,
а сервис помощника «Лиза» работает только там, где вы поднимете его со своим ключом.

Порядок такой: сервер Matrix (Synapse), серверные модули, настройка клиента, сборка,
затем по желанию уведомления, веб-версия, канал обновлений и «Лиза».

## 1. Что понадобится

- Сервер с Linux, доменное имя и сертификат TLS (HTTPS обязателен).
- Synapse (сервер Matrix) с базой PostgreSQL. SQLite не подойдёт: серверные модули
  используют возможности PostgreSQL.
- Обратный прокси (nginx, Caddy и т.п.), который отдаёт наружу Synapse по HTTPS.
- Для сборки Android: Flutter версии 3.47.4, Rust (библиотека шифрования), Android SDK.
- Для уведомлений на Android: проект Firebase (бесплатно).

## 2. Synapse

Установите Synapse по [официальной инструкции](https://element-hq.github.io/synapse/latest/setup/installation.html)
с PostgreSQL. Основные настройки в `homeserver.yaml`:

- `server_name` и `public_baseurl`: ваш домен, например `chat.example.org`;
- `enable_registration: false`: регистрации нет, аккаунты создаёт администратор;
- прокси должен пропускать к Synapse пути `/_matrix` и `/_synapse/client`
  (по второму работают модули DVChat).

Создайте администратора командой `register_new_matrix_user` из поставки Synapse.

## 3. Серверные модули

Модули лежат в каталоге [server/](../server/). Они дают вход по коду, друзей, комнаты
поддержки и истории, а также запрещают обычным людям создавать комнаты и приглашать.
Установка и настройка описаны в [server/README.md](../server/README.md). Без них приложение
запустится, но войти по ссылке не получится.

## 4. Настройка клиента

Все значения, привязанные к вашему серверу, задаются при сборке через файл настроек.
В репозитории лежит образец `dvchat.env.example`. Скопируйте его в `dvchat.env`
(этот файл в `.gitignore` и в репозиторий не попадёт) и заполните:

- `DVCHAT_HOMESERVER`: домен вашего Synapse без `https://`, например `chat.example.org`;
- `DVCHAT_PUSH_GATEWAY`: адрес шлюза уведомлений (раздел 6);
- `DVCHAT_UPDATE_URL`: адрес канала обновлений, оканчивается на `/` (раздел 8); можно оставить пустым.
- `DVCHAT_AUTH_URL`: публичный адрес сервиса [DV Auth](https://github.com/Godween69/DVAuth) без `/` на конце;
  нужен, чтобы подтверждать вход в другие ваши сервисы из DVChat по QR-коду и числу (раздел 10а); можно оставить пустым.

Файл подключается при каждой сборке и запуске параметром `--dart-define-from-file=dvchat.env`.

Остальное меняется в исходниках:

- `lib/config/app_config.dart`: `pushNotificationsAppId` (ваш идентификатор приложения);
- `android/app/build.gradle.kts`: `applicationId` (должен совпадать с `pushNotificationsAppId`);
- иконки и названия по вкусу (`assets/`, `android/app/src/main/res/`).

Выбор другого сервера в приложении отключён намеренно (`allowOtherHomeservers = false`),
регистрация тоже (`enableRegistration = false`). Это можно изменить в `app_config.dart`,
если нужен открытый мессенджер.

## 5. Сборка Android

Выпуск подписывается вашим ключом. Создайте ключ один раз и **храните его в надёжном месте**:
потеряв ключ, вы больше не сможете выпускать обновления для уже установленных приложений.

    keytool -genkey -v -keystore dvchat.jks -keyalg RSA -keysize 2048 -validity 10000 -alias dvchat

Положите рядом с проектом (в репозиторий они не попадают) два файла:

- `android/key.properties` со строками `storeFile` (путь к `.jks`), `storePassword`,
  `keyAlias`, `keyPassword`;
- `android/app/google-services.json` из вашего проекта Firebase (нужен для уведомлений).

Сборка:

    flutter pub get
    flutter gen-l10n
    flutter analyze
    flutter build apk --release --dart-define-from-file=dvchat.env

Если `DVCHAT_UPDATE_URL` в `dvchat.env` пуст, проверка обновлений ничего не делает.

Версия приложения имеет вид `MAJOR.MINOR.PATCH+номер_сборки`: она лежит в `pubspec.yaml`.
Номер сборки должен расти с каждым выпуском, по нему приложение понимает, что вышла новая версия.

## 6. Уведомления

Цепочка такая: Synapse отправляет уведомление на шлюз Matrix, шлюз передаёт его в Firebase (FCM),
Firebase доставляет на телефон.

1. Создайте проект в [Firebase](https://console.firebase.google.com), добавьте приложение Android
   с вашим `applicationId` и скачайте `google-services.json` (см. раздел 5).
2. Поднимите шлюз Matrix с поддержкой FCM. Подойдёт
   [Sygnal](https://github.com/element-hq/sygnal): в его настройках укажите идентификатор
   приложения (`pushNotificationsAppId`, к нему клиент дописывает `.` и идентификатор устройства,
   поэтому в Sygnal задаётся шаблон `ваш.идентификатор.*`) и данные доступа к FCM.
3. Укажите адрес шлюза в `dvchat.env` (`DVCHAT_PUSH_GATEWAY`),
   вида `https://push.example.org/_matrix/push/v1/notify`.
4. Если шлюз стоит в локальной сети, разрешите его адрес в `ip_range_whitelist` у Synapse.
5. Клиент использует формат уведомлений `event_id_only`: в уведомлении нет текста сообщения,
   телефон сам запрашивает его у Synapse.

Без этого шага приложение работает, но уведомления приходят только пока оно открыто.

## 7. Веб-версия

Нужны `git`, `curl`, `unzip`, `yq`, Rust и `flutter_rust_bridge_codegen`. Подготовка и сборка:

    sh scripts/prepare-web.sh
    WEBENV=$(mktemp); grep '^DVCHAT_HOMESERVER=' dvchat.env > "$WEBENV"
    flutter build web --release --base-href /app/ --dart-define-from-file="$WEBENV"

`--base-href` задаёт путь, по которому вы будете отдавать приложение (здесь `/app/`).
Для веба передаётся отдельный файл только с адресом сервера: всё, что попадает в сборку,
может оказаться в публичном `main.dart.js`, поэтому адрес канала обновлений и другие
секретные значения из `dvchat.env` туда класть нельзя.
Содержимое `build/web/` положите в каталог веб-сервера под этим путём, на том же домене,
что и Synapse. Скрипт `prepare-web.sh` изменяет рабочую копию (добавляет библиотеки
шифрования для веба), поэтому запускайте его в отдельной копии репозитория или откатывайте
изменения командой `git checkout`.

## 8. Канал обновлений (по желанию)

Любой веб-сервер, отдающий два файла по секретному адресу:

- `version.json`:

        {"versionCode": 12, "minVersionCode": 10, "notes": "Что нового", "sha256": "…", "size": 54000000}

  `versionCode` это номер сборки из `pubspec.yaml`; если он больше установленного, приложение
  предложит обновиться; `minVersionCode` необязателен (кто старше, тому обновление обязательно);
  `sha256` и `size` это контрольная сумма и размер файла `dvchat.apk`;
- `dvchat.apk`: собранный APK.

Приложение скачивает файл, проверяет сумму и предлагает установить его.
Адрес с секретной частью задаётся в `dvchat.env` (`DVCHAT_UPDATE_URL`, раздел 4).

## 9. «Лиза» (по желанию)

Вкладка «Лиза» в приложении работает с сервисом, **которого в репозитории нет**: у каждого
он свой. Клиент обращается по адресу `https://ваш-домен/lisa/v1/`:

- `GET status`: можно ли этому человеку пользоваться; код 403 означает «закрыто»;
- `POST chat`: тело `{"messages": [{"role": "user" или "assistant", "content": "…"}]}`,
  ответ приходит потоком.

В запросах клиент передаёт только токен Matrix самого пользователя (`Authorization: Bearer …`).
Ваш сервис должен проверить этот токен через Synapse (`/_matrix/client/v3/account/whoami`),
решить, допущен ли человек, и обращаться к языковой модели со **своим** ключом, который хранится
только на сервере. Не кладите ключи в приложение и в репозиторий. Пока сервиса нет,
вкладка «Лиза» недоступна, остальное приложение работает как обычно.

## 10. Первый вход

1. Создайте обычного пользователя (командой `register_new_matrix_user` или через административный
   интерфейс Synapse).
2. Администратор запрашивает одноразовый код входа у модуля `dv_social` (адрес `issue`,
   см. [server/README.md](../server/README.md)) и превращает его в ссылку
   `dvchat://login#…` или в QR-код.
3. Человек открывает ссылку или сканирует QR-код в приложении и входит. Если он входит
   с нового устройства, приложение спросит его ID из профиля.

## 10а. Подтверждение входа в другие сервисы (по желанию)

DVChat умеет подтверждать вход в сервисы, защищённые [DV Auth](https://github.com/Godween69/DVAuth)
(небольшой отдельный сервис второго фактора с открытым кодом). Сервис показывает QR-код и число.
В DVChat откройте **Настройки → Подтвердить вход**, наведите камеру на QR-код, проверьте, куда и с какого
адреса идёт вход, введите число с экрана и нажмите «Подтвердить». Ссылка `dvchat://auth#…` тоже работает.

Что нужно: развернуть DV Auth (его документация описывает всё по шагам), указать его публичный адрес
в `DVCHAT_AUTH_URL` и пересобрать приложение. Адрес берётся **только из сборки**, а не из QR-кода:
иначе чужой QR-код мог бы отправить подтверждение вашего аккаунта на посторонний сервер.
Подтверждение работает через одноразовый токен OpenID вашего Synapse; DV Auth проверяет его
у вашего сервера, пароль и токен доступа никуда не передаются.

## 11. Безопасность

Что защищает сервер, а что нет:

- Все правила (кто создаёт комнаты, кого можно приглашать, кто с кем дружит) проверяет **сервер**,
  а не приложение. Любой другой клиент (Element, веб, самодельный) получает ровно те же права,
  что и DVChat, и не больше.
- Проверка «входить можно только из DVChat» опирается на название устройства и подделывается.
  Это ограничение для порядка, а не защита от злоумышленника. Защищают права на сервере.
- Администратор входит любым клиентом и обходит все ограничения. Задайте ему длинный уникальный
  пароль и никому не передавайте его.
- Кодовая фраза шифрования хранится в базе сервера открытым текстом (подробности и способ
  отключить: [server/README.md](../server/README.md), раздел «О безопасности»).
- Запускайте Synapse **одним процессом**, без воркеров: одноразовые метки и счётчики попыток
  живут в памяти процесса.
- Закрепите версию образа Synapse (конкретная версия, проверенная с модулями), а не `latest`:
  модули используют внутренние возможности Synapse, и обновление может их сломать.
  После каждого обновления смотрите журнал и проверяйте раздел 12.
- Каталог пользователей оставьте по умолчанию (`user_directory.search_all_users: false`):
  тогда человек находит только тех, с кем у него есть общие комнаты.

Рекомендуемые настройки `homeserver.yaml`:

    enable_registration: false
    federation_domain_whitelist: []
    report_stats: false
    url_preview_enabled: false
    listeners:
      - port: 8008
        type: http
        tls: false
        x_forwarded: true
        resources:
          - names: [client, federation]

- `federation_domain_whitelist: []`: сервер не общается с чужими серверами.
- `x_forwarded: true`: нужен, если Synapse стоит за прокси. Без него ограничение попыток входа
  считает всех людей одним адресом. Если Synapse доступен напрямую, без прокси, этот параметр
  не включайте: иначе адрес можно подделать заголовком.
- Прокси пропускает наружу только `/_matrix` и `/_synapse/client`.

## 12. Проверка после установки

1. Обычный (не администратор) пользователь входит по ссылке из приложения и открывает чат с другом.
2. Тот же пользователь входит через Element или другой клиент: сервер должен отказать (`M_FORBIDDEN`).
3. Ту же ссылку открывают второй раз: «Ссылка недействительна или уже использована».
4. Регистрация закрыта. Команда должна вернуть `M_FORBIDDEN`:

        curl -s -X POST https://ваш-домен/_matrix/client/v3/register -H 'Content-Type: application/json' -d '{}'

5. Администратор входит в приложение и в панель управления.

## Что не входит в репозиторий

- ключи подписи (`*.jks`, `key.properties`) и `google-services.json`;
- адреса вашего сервера, шлюза уведомлений и канала обновлений (файл `dvchat.env`);
- сервис «Лиза» и ключи доступа к ИИ.
