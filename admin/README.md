# Админка DVChat

Локальная веб-панель администратора. Заменяет набор отдельных скриптов: люди, ссылки входа с QR-кодом,
группы с правами, комнаты, мастер настройки сборки. Зависимостей нет, нужен только Node 22 или Docker.

## Что умеет

Люди. Список, создание (логин, имя), одноразовая ссылка входа и QR-код, новая ссылка для существующего
человека, выход на всех устройствах, переименование, удаление с подтверждением вводом имени.

Группы. Администратор создаёт группу, назначает владельца и сразу выходит из неё: у людей его в списке
нет. Права выдаются флажками: приглашать, удалять людей, блокировать, удалять чужие сообщения,
менять название и фото, управлять правами. Права устроены лестницей уровней Matrix: выдавая верхнее,
вы даёте и нижние. Можно добавлять и убирать людей.

Комнаты. Список, фильтры (личные, группы, осиротевшие), удаление с подтверждением.

Комнаты умеют и очистку переписки: все сообщения стираются, сама комната и её участники остаются.
Если на сервере стоит свежий модуль dv_social, в комнате ставится метка очистки, и приложения (новые версии) сами стирают свою копию переписки.
Зашифрованные вложения панель с сервера стереть не может.

Люди. «Подружить людей…» делает двоих друзьями сразу и создаёт их личный чат. В карточке человека у каждого друга есть «Убрать из друзей…» (у обоих; чат и история остаются). «Отправить пуш…» шлёт текст выбранным людям от «DVChat»: приходит обычным уведомлением и остаётся в чате «DVChat». Эти действия работают через модуль dv_social на сервере.

Лиза (необязательный раздел, если у вас есть собственный ИИ-помощник с таким интерфейсом файлов). Показывает
состояние ключа сервиса моделей (только маска и остаток), порядок моделей с ценами и запасными, расход
в деньгах и токенах по дням, людям и моделям, журнал вопросов с ограниченным сроком хранения, настройки
поиска и доступа для каждого человека, а также редактируемый справочник по приложению. Сам ключ панель
не видит и не меняет.

Настройка. Проверка связи с Synapse и модулем dv_social. Мастер создаёт файл dvchat.env для сборки
приложения: вводить значения вручную в файл не нужно.

## Безопасность

Вход по паролю администратора (хранится только хеш scrypt). Сессия закрывается через 15 минут простоя.
Защита от подбора пароля, проверка адреса (Host), защита от подделки запросов (заголовок и Origin),
строгая политика CSP без встроенных скриптов и стилей. Токен Synapse лежит в секретном файле и
в журнал не попадает. Админка слушает только 127.0.0.1: заходите через SSH-туннель или свой обратный прокси с авторизацией. Все изменения
пишутся в data/audit.log без секретов.

Панель не читает переписку. Чаты зашифрованы, ключей у сервера нет.

## Первый запуск

1. Создайте каталог data рядом с docker-compose.yml и дайте доступ пользователю 1000:

        mkdir -p data && sudo chown 1000:1000 data && chmod 700 data

2. Пароль панели. Команда спросит пароль скрытым вводом:

        docker compose run --rm -it dvchat-admin node cli.mjs set-password

   Хеш записывается в data/secrets/dvadmin_password_hash (права 600).
3. Токен администратора Synapse. Команда спросит имя и пароль администратора Synapse и сохранит
   только токен:

        docker compose run --rm -it dvchat-admin node cli.mjs synapse-login

   Имя администратора по умолчанию admin (просто нажмите Enter). Пароль нигде не сохраняется.
4. Запуск:

        docker compose up -d --build

5. Откройте http://127.0.0.1:3101 и войдите.

## Настройки (переменные окружения)

DVADMIN_SYNAPSE_URL: адрес Synapse (по умолчанию http://synapse:8008).
DVADMIN_PORT: порт (3101). DVADMIN_BIND: адрес привязки (127.0.0.1; в контейнере 0.0.0.0, наружу порт публикуйте только на 127.0.0.1).
DVADMIN_ALLOWED_HOSTS: допустимые адреса через запятую (localhost,127.0.0.1).
DVADMIN_DATA_DIR: каталог данных (/data). DVADMIN_SECRETS_DIR: каталог секретов (по умолчанию /data/secrets).
DVADMIN_PASSWORD_HASH_FILE, DVADMIN_SYNAPSE_TOKEN_FILE: пути к секретным файлам.
DVADMIN_ENV_PATH: куда мастер записывает dvchat.env (по умолчанию /data/dvchat.env).
DVADMIN_LISA_CONFIG: путь к файлу настроек помощника (панель его правит; каталог должен быть доступен на запись).
DVADMIN_LISA_GUIDE: путь к текстовому справочнику по приложению (панель его правит).
DVADMIN_LISA_PANEL_DIR: каталог с состоянием, статистикой и каталогом моделей, который пишет сам помощник (панель только читает).
DVADMIN_IDLE_MINUTES (15), DVADMIN_ABSOLUTE_HOURS (8), DVADMIN_COOKIE_SECURE=1 при доступе по https.

## Требования к серверу

Synapse с правами администратора у учётной записи панели и модулями из каталога server/ репозитория
(dv_social, admin_only). Ссылки входа выдаёт эндпоинт issue модуля dv_social.

## Как это устроено на сервере с запретом приглашений

Если на сервере включено block_non_admin_invites (приглашать могут только администраторы), панель
всё равно управляет группами:

- права и исключение из группы выполняет сам владелец группы (панель на секунды заходит от его имени);
- добавление людей идёт через служебную комнату панели, где состоит только админ: у группы правило
  входа «restricted» с допуском по этой комнате, админ входит сам, добавляет людей через Admin API и выходит;
- при удалении человека панель выводит его из всех групп и чатов; единственного владельца группы
  удалить нельзя, пока не назначен другой;
- новая ссылка входа для существующего человека берёт его сохранённую на сервере кодовую фразу
  (keys/phrase), поэтому прежние ключи и переписка продолжают открываться.

## Проверка

    node --test test/app.test.mjs test/groups.test.mjs test/lisa_api.test.mjs

Тесты идут против настоящего Synapse: переменные SYNAPSE_URL, SYNAPSE_ADMIN_USER, SYNAPSE_ADMIN_PASSWORD.
Нужен тестовый Synapse с заглушкой dv_social; тесты создают людей и группы с именами-метками.

## Ограничения

Права в группах следуют лестнице уровней Matrix (нельзя дать «блокировать», не дав «удалять людей»).
Панель не может ни читать, ни расшифровывать чужие чаты.
