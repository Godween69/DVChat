# Серверные модули DVChat для Synapse

Четыре небольших модуля на Python для сервера Matrix [Synapse](https://github.com/element-hq/synapse).
Они подключаются к серверу и добавляют то, чего нет в самом Synapse. Приложение DVChat
обращается к ним по адресам вида `/_synapse/client/...`.

Модули рассчитаны на Synapse с базой **PostgreSQL**. Свои таблицы они создают сами
при первом обращении (имена начинаются с `dv_`).

## Что делает каждый модуль

- `admin_only.py`: запрещает обычным людям создавать комнаты, приглашать в них, публиковать комнаты
  и входить не из DVChat. Администратор ограничений не имеет. Исключение для личных чатов
  и служебных учётных записей делается через `dv_shared.py`.
- `dv_shared.py`: общая память двух модулей: одноразовые разрешения, которые живут одну минуту.
  Отдельного подключения не требует, это вспомогательный файл.
- `dv_social.py`: вход по одноразовому коду, ID людей, друзья и заявки, личные чаты с друзьями,
  профиль (день рождения), комнаты чата с администратором и форма обратной связи.
- `dv_stories.py`: истории на 24 часа: публикация, лента, просмотры, реакции, уборка.
  Работает отдельно от `dv_social`, но использует его таблицу друзей.

## Установка

1. Положите все четыре файла `*.py` в один каталог на сервере, например `/modules`.
2. Сделайте этот каталог доступным Synapse для импорта (переменная окружения `PYTHONPATH`).
   В Docker это выглядит так:

        services:
          synapse:
            environment:
              PYTHONPATH: /modules
            volumes:
              - ./synapse-modules:/modules:ro

3. Подключите модули в `homeserver.yaml`:

        modules:
          - module: admin_only.AdminOnly
            config:
              service_accounts: []
          - module: dv_social.DvSocial
            config: {}
          - module: dv_stories.DvStories
            config:
              server_name: chat.example.org

   Параметры:
   - `service_accounts`: список учётных записей (например `["@service:chat.example.org"]`),
     которым разрешено создавать комнаты, приглашать и входить любым способом. Нужен только если у вас
     есть свои служебные скрипты; пустой список означает «никому».
   - `server_name` у `dv_stories`: имя вашего сервера. Если не указать, берётся имя сервера Synapse.

4. Перезапустите Synapse. В журнале не должно быть ошибок про `dv_social` и `dv_stories`.

Порядок в списке `modules` не важен, но `admin_only` и `dv_social` должны быть подключены вместе:
личные чаты создаёт `dv_social`, а `admin_only` пропускает их по одноразовой метке.

## Адреса `dv_social` (`/_synapse/client/dv/…`)

Все адреса, кроме `login`, требуют токен доступа Matrix (заголовок `Authorization: Bearer …`).

- `login` (POST): вход по коду. Тело `{"code": "…", "dv_id": "…"}`. Токена не требует, защищён
  ограничением по адресу. Отдаёт данные для входа. Код одноразовый, действует до 72 часов,
  после пяти неверных ID сгорает.
- `issue` (POST): **только администратор**. Тело `{"user_id": "@имя:сервер", "password": "…",
  "passphrase": "…", "ttl_hours": 24}`. Возвращает одноразовый код. Ссылку для входа
  собирают так: `dvchat://login#` и далее base64url от `{"c": "код"}`. Из ссылки получается
  и QR-код.
- `me` (GET): мой ID. `friends` (GET), `friends/add`, `friends/remove`, `requests`,
  `requests/answer`: друзья и заявки. Добавление по ID или по QR-коду.
- `profile/get`, `profile/set`: день рождения (виден самому человеку, друзьям и администратору).
- `chat` (POST): открыть или создать личный чат с другом.
- `feedback` (POST): письмо администратору. `support/backfill`: создать комнаты с администратором
  для всех нынешних людей (разово, только администратор).
- `devices/logout_others`: выйти на всех устройствах, кроме текущего.
- `keys/phrase`: кодовая фраза шифрования самого человека (см. ниже).

Адреса `dv_stories` (`/_synapse/client/dvs/…`): `feed`, `publish`, `view`, `viewers`, `react`, `delete`.

## О безопасности (читайте перед запуском)

- Код входа хранится на сервере только в виде хеша (sha256). Пароль, который администратор передал
  при выдаче кода, хранится в базе до первого входа по этому коду и сразу после него удаляется.
  Если код так и не использовали, пароль стирается вместе с просроченной записью при следующей
  выдаче кода или попытке входа.
- **Кодовая фраза шифрования** (`passphrase`) хранится в базе сервера открытым текстом и
  отдаётся приложению самому человеку по токену (`keys/phrase`). Это сделано ради удобства:
  человек не вводит фразу вручную на новом устройстве. Цена вопроса: администратор сервера и тот,
  кто украл токен человека, могут получить фразу. Если для вас это недопустимо, уберите `keys/phrase`
  и храните фразу только у человека.
- Модуль `admin_only` отличает DVChat по названию устройства («DVChat …»). Это ограничение для
  порядка, а не защита от злоумышленника: название можно подделать.
- Ограничения частоты запросов хранятся в памяти процесса Synapse и сбрасываются при перезапуске.
- Одноразовые метки (`dv_shared`) тоже живут в памяти одного процесса, поэтому Synapse с воркерами
  не поддерживается: запускайте его одним процессом.
- Модули используют внутренние возможности Synapse (например, `self._api._hs`), поэтому после
  обновления Synapse их нужно проверять. Работоспособность гарантируется только для версии,
  на которой вы их запустили.
